MCP（Model Context Protocol）与智能体双层记忆架构

企业需求驱动（Issue #044）：基于 JSON-RPC 2.0 构建标准化 MCP Server/Client 工具资源总线，并实现短期滑动窗口 + SQLite 长期记忆的双层记忆系统

🎙️ 讲师旁白（从“胶水代码”到“USB-C 标准化外接总线”）：
MCP（Model Context Protocol）就像 AI 智能体的 USB-C 接口：无论底层是数据库、本地文件系统还是记忆库，只要实现统一的 JSON-RPC 2.0 initialize、tools/* 与 resources/* 协议，任何 Agent Host 都可以通过 MCPClient 即插即用。与此同时，DualMemoryManager 将“近期高频对话（短期滑动窗口）”与“跨会话事实沉淀（SQLite 长期记忆）”解耦，让智能体既省 Token 又不会遗忘核心知识。

一、MCP 协议交互时序图（JSON-RPC 2.0）

Agent Host 通过 MCPClient 与 MCPServer 进行标准化 JSON-RPC 2.0 通信，完成能力协商、工具调用与资源读取：

sequenceDiagram autonumber participant Host as Agent Host participant Client as MCPClient participant Server as MCPServer participant Mem as DualMemoryManager Host->>Client: initialize() Client->>Server: JSON-RPC 2.0 {"method": "initialize"} Server-->>Client: {"protocolVersion": "2024-11-05", "capabilities": {...}} Host->>Client: list_tools() / list_resources() Client->>Server: JSON-RPC 2.0 {"method": "tools/list"} Server-->>Client: 返回工具 Schema 描述符列表 Host->>Client: call_tool("memory_store", {key, value}) Client->>Server: JSON-RPC 2.0 {"method": "tools/call", ...} Server->>Mem: remember(key, value) Mem-->>Server: 写入 SQLite 长期记忆 Server-->>Client: {"content": [...], "isError": false} Host->>Client: read_resource("memory://stats") Client->>Server: JSON-RPC 2.0 {"method": "resources/read", ...} Server-->>Client: {"contents": [{"uri": "memory://stats", ...}]}

二、核心架构与协议对照表

核心模块 职责定位 关键方法 / 协议规范
MCPServer 标准 JSON-RPC 2.0 服务端，托管工具与只读资源 initialize、tools/list、tools/call、resources/list、resources/read
MCPClient Agent 侧协议客户端，封装请求编号与错误解析 自动递增 id，遇到 JSON-RPC error 抛出 MCPClientError
短期滑动窗口 控制最近对话上下文长度，防止 Token 膨胀 按 session_id 维护 deque(maxlen=window_size)，支持 add_turn() 与淘汰
SQLite 长期记忆 跨进程/跨会话持久化关键事实与偏好 按 namespace 隔离，支持 remember()、recall_key()、search_long_term()

三、核心代码实战：MCP 握手、记忆工具调用与上下文融合

from pathlib import Path
from zhishu_agent import MCPClient, create_memory_enabled_mcp_server

server, memory = create_memory_enabled_mcp_server(Path("zhishu_mem.db"), window_size=3)
client = MCPClient(server=server)

# 1. MCP 握手与工具发现
client.initialize(client_name="zhishu-host")
print("可用工具:", [t["name"] for t in client.list_tools()])

# 2. 通过 MCP 工具写入与检索长期记忆
client.call_tool("memory_store", {
    "key": "pref_lang",
    "value": "用户偏好使用 Python 3.11 与 FastAPI",
    "namespace": "user-chenmo",
    "tags": ["偏好", "技术栈"],
})
hits = client.call_tool("memory_search", {"query": "FastAPI 技术栈", "namespace": "user-chenmo"})
print("检索结果:", hits["content"][0]["text"])

# 3. 写入短期滑动窗口并构建融合上下文
memory.add_turn("sess-01", "user", "帮我创建一个新的后端服务")
ctx = memory.build_context("sess-01", "后端技术栈", namespace="user-chenmo", top_k=1)
print("融合上下文:", ctx)

四、课后思考与自检清单

点击展开：MCP 中参数校验失败（-32602）与工具内部异常（isError=True）有何区别？

当请求缺少 inputSchema.required 中声明的必填字段或调用了不存在的工具名时，属于协议层面的 Invalid Params (-32602)，服务端应返回标准 JSON-RPC error 对象；而当参数合法但工具在执行外部业务时发生异常（如网络超时），服务端应返回正常 JSON-RPC result 并在内部标记 "isError": true，以便大模型感知错误原因并自主重试或降级。

点击展开：为什么长期记忆需要按 namespace 隔离，而短期记忆按 session_id 隔离？

短期记忆绑定单次对话流（session_id），不同对话窗口的上下文不能混杂；而长期记忆沉淀的是用户画像或租户级知识（namespace），同一用户在多个不同 session_id 中都应能跨会话召回自己的长期偏好。
