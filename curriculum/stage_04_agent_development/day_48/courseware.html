里程碑项目 3（Part 1）：多 Agent 智能办公助手核心编排与工具集

企业需求驱动（Issue #048）：构建 ResearchAgent / CalendarAgent / MailAgent 协同架构、6 大办公工具与 SQLite 断点审批恢复

🎙️ 讲师旁白（为什么需要多 Agent 分工 + 高危操作中断审批？）：
在企业办公自动化中，调研、日程协调与邮件沟通是三个职责截然不同的领域。将所有工具塞进一个单体 Agent 会导致提示词臃肿与越权风险；而直接自动发邮件或约会议更可能造成“不可逆的职场事故”。今天我们用 OfficeSupervisor 统筹三大专职 Agent，并通过 SQLiteCheckpointer + interrupt_before 为高危动作加上“人类最后一道确认防线”。

一、多 Agent 协同与 HITL 断点恢复架构

每一次办公协同请求均经历“主管拆解计划 → 专职 Agent 依次执行 → 高危工具触发 interrupt_before 落盘 SQLite → 人工审批（批准/微调/拒绝）→ 断点续跑”完整闭环：

flowchart TD REQ(["用户办公请求"]) --> SUP["OfficeSupervisor.plan_tasks() 拆解任务"] SUP --> RES["ResearchAgent: search_company_docs + web_search"] RES --> CAL["CalendarAgent: list_calendar 日程冲突检查"] CAL --> CHK1{"create_meeting 需人工审批?"} CHK1 -->|"挂起写入 SQLite"| WAIT1(["interrupted: create_meeting"]) WAIT1 -->|"resume(approved=True)"| MTG["执行 create_meeting"] WAIT1 -->|"resume(approved=False)"| REJ(["status=rejected"]) MTG --> MAIL["MailAgent: draft_email 汇总前序产出"] MAIL --> CHK2{"send_email 需人工审批?"} CHK2 -->|"挂起写入 SQLite"| WAIT2(["interrupted: send_email"]) WAIT2 -->|"resume(approved=True)"| SEND["执行 send_email"] WAIT2 -->|"resume(approved=False)"| REJ SEND --> DONE(["status=completed · 返回汇总报告"])

二、三大专职 Agent 与 6 大办公工具矩阵

Agent 角色 核心职责 授权工具（最小权限） 风险等级
ResearchAgent 企业内部文档与外部行业资料检索 search_company_docs, web_search 低危只读
CalendarAgent 查询日程冲突、创建企业正式会议 list_calendar, create_meeting create_meeting 高危（默认中断）
MailAgent 汇总前序产出起草邮件并正式发送 draft_email, send_email send_email 高危（默认中断）

三、SQLite 断点持久化与审批恢复实战

from zhishu_agent import OfficeSupervisor, OfficeWorkspace, SQLiteCheckpointer

ws = OfficeWorkspace()
sup = OfficeSupervisor(
    workspace=ws,
    checkpointer=SQLiteCheckpointer("office_checkpoints.db"),
    interrupt_before={"create_meeting", "send_email"},
)

# 1. 启动协同任务 -> 在 create_meeting 前自动挂起
res1 = sup.run("请调研 Q4 战略文档，预约会议并发送邮件通知", thread_id="demo-01")
print(res1["status"], res1["pending_action"]["tool_name"])  # interrupted create_meeting

# 2. 人工批准并微调会议时间 -> 推进至 send_email 前再次挂起
res2 = sup.resume("demo-01", approved=True, modified_args={"start_time": "16:30"})
print(res2["status"], res2["pending_action"]["tool_name"])  # interrupted send_email

# 3. 人工批准发送邮件 -> 全部完成
res3 = sup.resume("demo-01", approved=True)
print(res3["status"])  # completed

四、课后思考与自测

思考题：为什么我们在 OfficeSupervisor.resume() 中支持传入 modified_args 参数？如果只允许“全部通过”或“全部拒绝”，在实际企业办公场景中会遇到什么痛点？

点击查看参考解答

在真实办公中，审批人往往认同 Agent 的主体意图（如“确实需要约一个评审会”或“确实要发这封同步邮件”），但经常需要微调具体细节（例如把会议时间从 16:00 改到 16:30，或补充一个抄送人）。如果不支持 modified_args，用户只能拒绝后重新从头跑一遍调研与规划，不仅浪费 Token 和时间，还破坏了协同体验。
