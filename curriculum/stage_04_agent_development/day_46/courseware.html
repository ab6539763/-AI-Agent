Agent 稳定性、可观测性（LangSmith 风格追踪）与安全护栏

企业需求驱动（Issue #046）：构建全链路嵌套 Tracing、PII 脱敏与注入拦截护栏、以及 CircuitBreaker 熔断降级机制

🎙️ 讲师旁白（从“能跑”到“可观测、可防呆、可熔断”）：
智能体上线后的三大噩梦分别是：排障黑盒、安全越狱与隐私泄露、以及上游超时引发的级联雪崩。今天我们将为智枢平台打造三大生产级防护底座：Tracer / TraceSpan（LangSmith 风格嵌套链路追踪与成本计量）、GuardrailsEngine（PII 脱敏、Prompt Injection 拦截与 JSON Schema 输出校验），以及 CircuitBreaker / LatencyBudget（三态熔断器与延迟预算守卫）。

一、全链路可观测性与护栏架构

每一次智能体调用均经过“输入护栏 → 受追踪与熔断保护的 Agent 执行 → 输出护栏 → TraceStore 链路落盘”四重防线：

flowchart TD REQ(["用户输入 / API 请求"]) --> IN_GUARD["Input Guardrail: Prompt Injection 拦截 + PII 脱敏"] IN_GUARD -->|"命中注入攻击"| BLOCKED(["快速拒绝: status=blocked"]) IN_GUARD -->|"校验通过"| AGENT["Traced Agent: Tracer 嵌套 Span + CircuitBreaker + LatencyBudget"] AGENT -->|"熔断 OPEN / 超时"| FALLBACK(["稳定降级: CircuitBreakerOpenError / LatencyBudgetExceededError"]) AGENT -->|"返回原始结果"| OUT_GUARD["Output Guardrail: JSON Schema 校验 + 输出端 PII 脱敏"] OUT_GUARD -->|"Schema 不合法"| INVALID(["结构拦截: status=invalid_output"]) OUT_GUARD -->|"校验通过"| RESP(["返回安全结构化结果"]) IN_GUARD -.->|"guardrail span"| STORE[("TraceStore: 树形链路 / Token 费用 / JSONL")] AGENT -.->|"chain / llm / tool spans"| STORE OUT_GUARD -.->|"guardrail span"| STORE

二、三大核心模块与工程设计

核心组件 解决的生产痛点 关键设计要点
Tracer & TraceSpan 多步 Agent 调用链黑盒、耗时与 Token 成本难核算 基于 contextvars.ContextVar 自动关联 trace_id 与 parent_run_id，记录毫秒耗时、TokenUsage、费用及异常栈，支持树形重建与 JSONL 导出。
GuardrailsEngine 用户手机号/身份证/邮箱泄露、Prompt Injection 越狱、非结构化输出崩溃 先身份证再手机号的正则顺序脱敏；中英文注入规则拦截；轻量级 JSON Schema 校验与输出端二次脱敏。
CircuitBreaker & LatencyBudget 下游模型故障导致线程池耗尽、长尾慢请求拖垮 SLA CLOSED / OPEN / HALF_OPEN 三态熔断状态机，达到失败阈值快速失败，冷却后半开探测自动恢复。

三、核心代码实战示例

1. 使用 GuardedAgentRunner 串联输入护栏、嵌套追踪与输出护栏

from zhishu_agent import CircuitBreaker, GuardedAgentRunner, GuardrailsEngine, LatencyBudget, Tracer

runner = GuardedAgentRunner(
    tracer=Tracer(),
    guardrails=GuardrailsEngine(),
    circuit_breaker=CircuitBreaker(failure_threshold=3, recovery_timeout_s=1.0),
    latency_budget=LatencyBudget(max_latency_ms=2000.0, enforce=True),
)

def agent_fn(sanitized_input: str, tracer: Tracer) -> dict:
    with tracer.start_span("llm_call", span_type="llm") as span:
        span.record_usage(prompt_tokens=320, completion_tokens=140)
        return {"answer": f"已处理：{sanitized_input}", "risk_level": "low"}

result = runner.run("联系我 13812345678", agent_fn=agent_fn)
print(result["status"], result["trace_summary"])
