AgentExecutor 负责驱动 ToolCallingAgent 在 max_iterations 预算内执行 Plan → Act → Observe 循环，并将每一步的 (AgentAction, observation) 忠实记录在 intermediate_steps 中：

二、@tool 装饰器与 StructuredTool 自动 Schema 提取

通过 Python 标准库 inspect.signature 与 typing.get_type_hints，@tool 在装饰函数时自动完成三件事：

提取维度 Python 反射机制 生成的 OpenAI Tool Schema 字段
工具名称 func.__name__ 或 @tool("custom") function.name
工具与参数描述 inspect.getdoc(func) + Args: 正则解析 function.description & properties[k].description
参数类型与必填项 get_type_hints() + Parameter.empty parameters.properties & parameters.required

四、课后随堂思考与参考答案

问题 1：为什么 AgentExecutor 在工具抛出 PermissionError 时，选择把异常文本作为 observation 写回 intermediate_steps，而不是直接让整个服务崩溃？

点击展开参考答案

将受控异常（如参数缺失、路径穿越拦截）转化为 observation 反馈给 ToolCallingAgent，既能阻止越权操作真正发生，又能让大模型在下一轮推理中感知错误原因并向用户输出合理解释或尝试修正参数，从而提升系统的鲁棒性与可观测性。

问题 2：为什么 @tool 强制要求函数必须包含非空 Docstring？

点击展开参考答案

在 Function Calling 机制中，大模型并看不到工具的 Python 函数体源码，它只能依据 name、description 和 parameters Schema 来判断“何时该调用哪个工具”。缺失 Docstring 会导致模型无法理解工具语义，进而引发严重的参数幻觉或误调用。
