一、Stage 4 多智能体基准评测架构

BenchmarkRunner 将安全护栏前置拦截与多场景执行解耦，确保安全红线用例在零 Token 消耗下快速拦截，同时对正常用例执行延迟、成本与输出 PII 脱敏校验。

flowchart TD SUITE["BenchmarkSuite (9 用例: ReAct / SQL Agent / Office Multi-Agent)"] --> GUARD_IN["BenchmarkGuardrail.check_input: 注入与高危 SQL 拦截"] GUARD_IN -->|"命中红线"| BLOCKED(["快速拦截: blocked=True, tokens=0"]) GUARD_IN -->|"安全放行"| EXEC["Scenario Executor: react / sql_agent / office_multi_agent"] EXEC --> GUARD_OUT["BenchmarkGuardrail.sanitize_output: PII 自动脱敏"] BLOCKED --> REPORT["BenchmarkReport: 成功率 / Avg & P95 延迟 / Token 成本 / 护栏通过率"] GUARD_OUT --> REPORT REPORT --> GATE{"Release Gate 门禁校验"}

二、四大核心评测维度与门禁标准

评测维度 核心指标 Stage 4 验收门禁 工程意义

三、核心代码实战：运行 Stage 4 基准评测套件

from zhishu_agent import BenchmarkRunner, build_default_benchmark_suite

runner = BenchmarkRunner()
suite = build_default_benchmark_suite()
report = runner.run_suite(
    suite,
    min_success_rate=0.85,
    min_guardrail_rate=1.0,
    max_avg_latency_ms=500.0,
)
print(report.to_markdown())
assert report.gate_passed is True

四、Project 3 答辩高频 Q&A 演练

Q1：为什么把 Prompt Injection 与高危 SQL 检查放在执行器之前？

前置护栏可以在请求进入 LLM 或数据库之前直接阻断恶意指令，既消除越狱与删库风险，又避免浪费任何推理 Token（实测拦截用例 total_tokens = 0）。

Q2：如何将离线基准套件平滑接入真实大模型或生产环境？

通过 BenchmarkRunner.register_executor(scenario, custom_fn) 即可将 ReAct、SQL Agent 或 Office Multi-Agent 的离线仿真器替换为真实 LangGraph / MCP 执行器，评测指标与发布门禁逻辑完全复用。
