多智能体协作系统：Supervisor 模式（Researcher + Analyst + Writer）

企业需求驱动（Issue #043）：构建职责清晰、交接可审计且具备 max_rounds 防死循环熔断的企业级多智能体研报团队

🎙️ 讲师旁白（从“全能单兵”到“专职协同团队”）：
当单一 Agent 同时承担检索、分析与撰稿时，系统提示词会迅速膨胀，工具调用准确率随之下降。Day 43 我们将引入企业级 Supervisor-Worker 多智能体架构：由 ResearcherAgent 专注检索事实，AnalystAgent 专注洞察与风险评估，WriterAgent 专注结构化报告撰写，并由 SupervisorOrchestrator 集中统筹任务路由、记录 agent_handoffs 审计轨迹及执行 max_rounds 熔断保护。

一、Supervisor 多智能体协作架构

flowchart TD USER(["用户输入: 研究主题 topic"]) --> SUP["SupervisorOrchestrator<br/>(任务路由 · 交接审计 · max_rounds 熔断)"] SUP <-->|"1. 下发调研指令 / 返回 findings"| RES["ResearcherAgent<br/>(信息调研员)"] SUP <-->|"2. 下发分析指令 / 返回 insights & risks"| ANA["AnalystAgent<br/>(数据分析师)"] SUP <-->|"3. 下发撰稿指令 / 返回 report"| WRI["WriterAgent<br/>(报告撰稿人)"] SUP -->|"4. 路由至 FINISH 或触发 max_rounds"| OUT(["输出 OrchestrationResult<br/>(final_report + agent_handoffs)"])
核心组件职责定位产出 Artifacts
AgentWorker专职智能体抽象基类，定义统一 execute(task, context) 契约WorkerResult
ResearcherAgent围绕研究主题检索背景资料、行业动态与核心事实findings
AnalystAgent对调研事实进行结构化对比、量化指标与风险评估insights, risks, metrics
WriterAgent汇总调研与分析成果，撰写可直接交付的 Markdown 研报report
SupervisorOrchestrator中央调度、路由决策、agent_handoffs 追踪与 max_rounds 熔断OrchestrationResult

二、Supervisor vs Peer-to-Peer 架构权衡

评估维度Supervisor 模式（本课实现）Peer-to-Peer 网状模式
扩展复杂度O(N) 线性增长，Worker 之间解耦O(N²) 交互边膨胀，Prompt 易失控
死循环防护集中维护 max_rounds，单点精准熔断缺乏全局视角，易产生隐蔽环形交接
审计可观测性天然沉淀完整 agent_handoffs 轨迹需要额外分布式追踪总线还原链路

三、核心代码实战

1. 启动默认 Supervisor 多智能体团队

from zhishu_agent import SupervisorOrchestrator

orchestrator = SupervisorOrchestrator(max_rounds=6)
result = orchestrator.run("企业级多智能体系统的 Supervisor 编排与防死循环治理")

print("执行状态:", result.status, "| 使用轮次:", result.rounds_used)
for rec in result.agent_handoffs:
    print(f"Round {rec.round_num}: {rec.from_agent} -> {rec.to_agent}")

2. 自定义路由与 max_rounds 熔断防护

def cyclic_router(ctx, handoffs, available):
    target = "analyst" if len(handoffs) % 2 == 1 else "researcher"
    return target, "补充调研与分析"

guarded = SupervisorOrchestrator(max_rounds=4, router_fn=cyclic_router)
res = guarded.run("死循环熔断测试")
assert res.status == "max_rounds_reached"

四、课后实战作业（点击展开参考答案）

作业 1： 对比 Supervisor 与 Peer-to-Peer 在扩展性、死循环防护和审计可观测性上的差异，给出企业选型结论。

查看参考答案要点

企业级强流程、高合规场景优先选择 Supervisor 模式：路由复杂度 O(N)、可由中央节点统一执行 max_rounds 熔断，并天然产出 agent_handoffs 审计日志。

作业 2： 编写一个在 researcher 与 analyst 间无限乒乓切换的 router_fn，验证 max_rounds=4 能够强制熔断并返回 status="max_rounds_reached"。

查看参考答案代码 
orchestrator = SupervisorOrchestrator(
    max_rounds=4,
    router_fn=lambda ctx, h, avail: ("analyst" if len(h) % 2 else "researcher", "循环测试"),
)
res = orchestrator.run("高并发架构复盘")
assert res.status == "max_rounds_reached" and res.rounds_used == 4

作业 3： 继承 AgentWorker 新增 ReviewerAgent，构建四阶段（Researcher → Analyst → Writer → Reviewer）质量门禁流。

查看参考答案思路
