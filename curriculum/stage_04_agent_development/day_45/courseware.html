三、核心代码实战：声明式 DSL 与变量插值

以下片段展示了如何声明一个带条件路由的 RAG 工作流并交由 WorkflowEngine 执行：

from zhishu_agent import WorkflowEngine, build_default_rag_workflow_dsl

dsl = build_default_rag_workflow_dsl()
engine = WorkflowEngine()

# 场景 1：命中知识库 -> 走 llm_rag -> end_hit
res_hit = engine.run(dsl, inputs={"query": "请假和报销怎么审批？"})
print("命中路由:", res_hit.outputs["route"], "轨迹:", [r.node_id for r in res_hit.execution_trace])

# 场景 2：未命中知识库 -> 走 llm_fallback -> end_miss
res_miss = engine.run(dsl, inputs={"query": "今天食堂有什么菜？"})
print("兜底路由:", res_miss.outputs["route"], "轨迹:", [r.node_id for r in res_miss.execution_trace])

四、第七周综合测验（Week 7 Assessment）精选自测

完整 10 道单选题 + 2 道编程实战题及解析见 docs/weekly_quiz_and_answers.md，以下为高频核心考点自测：

自测题 1：为什么低代码 Workflow DSL 解析阶段必须做 Kahn 算法环检测？

声明式工作流面向非研发人员配置，若误连出 A -> B -> A 的环路会导致运行期无限死循环与 Token 爆炸；通过 Kahn 拓扑排序可在执行前毫秒级拦截非法环。

自测题 2：在带有 interrupt_before 的 LangGraph 状态图中，resume() 首轮为什么要跳过中断检查？

因为断点正是停留在被拦截节点之前；若恢复首轮不跳过拦截检查，引擎会在同一节点再次触发 interrupted，导致人工永远无法推进任务。
