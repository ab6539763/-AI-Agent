一、为什么需要 Agent：Chain vs. ReAct 对比

维度 传统 Chain（固定流水线） ReAct Agent（自主推理循环）
控制流 静态有向无环图（DAG），步骤写死 动态循环（while / for），由模型决定下一步
工具调用 预设固定顺序，无法根据结果动态追加 按需选择工具（查制度 -> 算预算 -> 再核验）
容错与自愈 某一步参数错误即整体失败 将报错包装为 Observation 反馈给模型自我修正
风险控制 天然有界，不会死循环 必须显式配置 max_steps 步数上限守卫

二、纯 Python ReAct 循环架构图

每一轮迭代都严格遵循 Thought -> Action -> Action Input -> Observation 闭环，直至输出 Final Answer 或触发 max_steps 熔断：

flowchart TD Q["用户问题 Query"] --> INIT["初始化 steps = [] , step_idx = 1"] INIT --> GUARD{"step_idx <= max_steps ?"} GUARD -->|"否"| STOP_MAX["安全熔断: stopped_reason = max_steps"] GUARD -->|"是"| PLAN["Planner (Mock/LLM) 生成 ReAct 文本"] PLAN --> PARSE["parse_react_output() 正则解析"] PARSE -->|"解析失败"| STOP_ERR["stopped_reason = parse_error"] PARSE -->|"Final Answer"| STOP_OK["记录 ReActStep 并返回 Final Answer"] PARSE -->|"Action + Action Input"| TOOL{"工具是否已注册?"} TOOL -->|"否"| OBS_ERR["Observation = 未知工具错误提示"] TOOL -->|"是"| EXEC["执行工具: AST calculator / knowledge_search"] EXEC --> OBS_OK["追加 Observation 到 steps"] OBS_ERR --> NEXT["step_idx += 1"] OBS_OK --> NEXT NEXT --> GUARD

三、核心工程要点与安全防线

1. 安全 AST 计算器（严禁 eval()）

使用 ast.parse(expr, mode="eval") 递归求值，仅放行数字常量与四则/幂运算节点，从语法树层面彻底拦截 __import__('os').system(...) 等恶意代码注入。

2. 正则协议解析与异常隔离

_THOUGHT_RE = re.compile(r"Thought:\s*(.*?)(?=\n(?:Action|Final Answer):|\Z)", re.DOTALL)
_FINAL_ANSWER_RE = re.compile(r"Final Answer:\s*(.+)\Z", re.DOTALL)
_ACTION_RE = re.compile(r"Action:\s*([A-Za-z0-9_.-]+)")
_ACTION_INPUT_RE = re.compile(r"Action Input:\s*(.*?)(?=\nObservation:|\Z)", re.DOTALL)

  Action Input: 高级工程师 差旅 住宿 报销 标准

[Step 2]
  Thought: 已查到高级工程师住宿标准为 450 元/晚，接下来使用计算器计算 4 晚的总预算。
  Action: calculator
  Action Input: 450 * 4
  Observation: 1800
[Step 3]
  Thought: 已经拿到精确的计算结果，可以汇总输出最终答案。
  Final Answer: 根据星辰数科差旅制度，高级工程师住宿报销上限为 450 元/晚，总住宿预算上限为 1800 元。
