通过 OpenAI 兼容协议（/v1/chat/completions） 对上层智能体屏蔽底层推理引擎差异，实现“本地 Ollama 开发调试 → 生产 vLLM 高并发集群”的零代码热切换：

flowchart LR APP["智枢智能体应用层 (Agent / RAG / Workflow)"] -->|"标准 OpenAI ChatCompletions 请求"| GW["OpenAICompatibleGateway (httpx + MockTransport)"] GW -->|"环境切换: 本地开发 / CPU / Mac"| OLLAMA["Ollama 推理服务 (:11434/v1) · GGUF / 静态 KV 槽位"] GW -->|"环境切换: 生产 GPU 集群"| VLLM["vLLM 推理服务 (:8000/v1) · AWQ / PagedAttention + Continuous Batching"] OLLAMA --> BENCH["ThroughputBenchmarker (TTFT / TPS / P95 压测门禁)"] VLLM --> BENCH

二、Ollama vs vLLM 核心架构差异

对比维度 Ollama（基于 llama.cpp） vLLM（生产级 GPU 推理引擎）
典型定位 本地开发、个人 Mac/PC、低并发内网工具 企业级多租户高并发 GPU API 服务集群
KV Cache 管理 静态连续内存预分配，长短请求混跑存在显存碎片 PagedAttention 分页动态分配，显存利用率 > 96%
批处理调度 固定并行槽位（OLLAMA_NUM_PARALLEL），超限排队阻塞 Continuous Batching 迭代级调度，请求完成即释放并插队
高并发扩展性 并发超过槽位后 TTFT 急剧恶化，总 TPS 很快触顶 随并发增加系统总 TPS 近似线性扩展，P95 延迟平滑可控

三、核心代码模式：OpenAI 兼容网关热切换

from zhishu_agent import InferenceBackendConfig, OpenAICompatibleGateway

# 1. 默认接入本地 Ollama
with OpenAICompatibleGateway(InferenceBackendConfig.ollama_default()) as gw:
    res_dev = gw.chat_completions([{"role": "user", "content": "生成只读 SQL 查询"}])

    # 2. 一键热切换至生产 vLLM，上层业务调用签名完全不变
    gw.switch_backend(InferenceBackendConfig.vllm_default())
    res_prod = gw.chat_completions([{"role": "user", "content": "生成只读 SQL 查询"}])

四、课后思考与自测

点击查看：为什么并发压测同时关注 TTFT 与 System TPS？

TTFT（首字延迟）受 Prefill 算力与队列等待影响，决定实时流式对话用户的“响应体感”；System TPS（系统总吞吐）受 Decode 显存带宽与 Batch Size 影响，决定单张 GPU 每秒能服务多少并发用户的算力成本。
