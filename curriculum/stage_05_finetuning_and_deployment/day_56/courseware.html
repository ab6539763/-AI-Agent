一、全栈容器化部署拓扑架构

生产环境通过 Nginx 统一接入外部流量，后端 FastAPI 容器在隔离的桥接网络 zhishu-net 中协同向量库 Qdrant、SQLite、Redis 与私有化 vLLM 推理服务：

flowchart TD CLIENT["企业内网客户端 / 浏览器"] --> NGINX["Nginx 反向代理 (:80 / :443)"] NGINX -->|"proxy_pass :8000"| API["zhishu-api (FastAPI, USER zhishu)"] API -->|"HTTP :6333"| QDRANT["VectorDB: Qdrant (qdrant_storage)"] API -->|"卷挂载 /app/data"| SQLITE["SQLite 状态库 (zhishu_data)"] API -->|"TCP :6379"| REDIS["Redis 缓存/队列 (redis_data)"] API -->|"OpenAI 兼容 :8001/v1"| VLLM["vLLM 私有化推理引擎"]

二、生产级 Dockerfile 五大安全基线

安全与工程基线 实现指令 / 规范 核心收益
多阶段构建 FROM python:3.11-slim AS builder → AS runtime 剥离构建期工具链，仅拷贝 /opt/venv，缩减镜像体积与 CVE 风险
非 root 运行 useradd --system --uid 10001 zhishu + USER zhishu 遵循最小权限原则，防止容器逃逸或越权篡改宿主机挂载文件
容器健康检查 HEALTHCHECK --interval=30s ... /health 实时探测进程存活性，异常时由编排器自动摘除流量或重启
端口显式声明 EXPOSE 8000 明确服务监听边界，便于反向代理与运维监控自动发现
零硬编码密钥 严禁在 ENV / ARG 写入真实凭据 避免 docker history 明文泄漏 API Key 或数据库密码

三、Docker Compose 编排与 `.env` 密钥隔离

核心要点：通过 depends_on 结合 condition: service_healthy 消除启动竞争，并通过 .env.example + .env 实现配置与代码仓库彻底解耦。

depends_on:
  qdrant:
    condition: service_healthy
  redis:
    condition: service_healthy

四、课后思考与自动化验证

点击查看：为什么不能把 `.env` 提交到 Git，而只提交 `.env.example`？

Git 历史具有不可变性，一旦真实密钥（如 sk-... 或数据库密码）被提交到仓库，即便后续删除也会永久残留在 commit 历史中。.env.example 仅保留键名与安全占位符，真实凭据在部署机或 CI/CD Secret 中注入。
