# Day 68 课后练习与参考答案

## 练习一：架构盲区诊断与补全
**题目**：某候选人在面试“高并发智能客服系统（1000 QPS，P99 ≤ 800ms，月预算 ¥85,000）”时给出如下方案：
- 组件：`["FastAPI", "Milvus HNSW", "GPT-4o API"]`
- 缓存：`无`
- 降级：`无`
- 护栏：`无`
- 成本控制：`无`

请使用 `zhishu_agent.system_design_sim` 对该方案进行评估，并写出至少 4 条核心改进措施使其达到 **S 级（≥ 90 分）** 且月度预算达标。

### 参考答案
1. **引入网关限流与并发控制**：在 API Gateway 层增加令牌桶限流（RPM/TPM）与背压队列，防止大促流量翻倍打垮推理池。
2. **引入 Redis 语义缓存**：对高频重复客服问题（如发货时间、退货流程）配置 `cosine >= 0.92` 语义缓存，拦截 ~35% 请求直出。
3. **引入大小模型成本路由**：65% 常规查单/FAQ 路由至轻量 7B 模型，仅复杂客诉路由至旗舰模型，将月度预估成本从 ¥270,000 降至 ¥74,100（低于 ¥85,000 预算）。
4. **补充熔断降级、安全护栏与全链路可观测**：配置大模型超时熔断降级策略、Prompt 注入与高危工具调用拦截，并接入 Langfuse / Prometheus 监控 TTFT 与错误率。

## 练习二：项目深挖白板演练（3 分钟口述题）
**题目**：面试官问：“你在智枢平台中做过最有挑战的性能或成本优化是什么？请用数据说明。”

### 参考答案（STAR + Trade-off 结构）
- **Situation**：智枢平台在接入集团 100 万文档后，早高峰 200 QPS 下 P99 延迟飙升至 2.4 秒，且单月大模型调用成本接近 7 万元，远超部门 3.5 万元预算。
- **Task**：我主导了检索与推理链路的性能与成本专项治理，目标是在不降低 Recall@5 的前提下将 P99 压到 1.2s 内、月成本控制在 3.5 万以内。
- **Action**：
  1. 在检索前增加 **Redis 向量语义缓存**，对相似度 ≥ 0.92 的高频提问直接流式返回，拦截了 35% 的无效模型调用；
  2. 设计 **意图复杂度路由器**，将 65% 的简单制度问答分流至本地微调的 Qwen-7B，复杂多跳推理才走旗舰模型；
  3. 配合 **Milvus 分片 + Cross-Encoder 批处理重排** 与 **Langfuse 全链路耗时监控**，精准定位并消除慢查询。
- **Result & Trade-off**：P99 延迟从 2.4s 降至 950ms（-60%），月度推理成本从 ¥67,500 降至 ¥18,525（-72.5%）。代价是语义缓存可能带来极低概率的“近似误命中”，我们通过按文档版本失效缓存和设置 0.92 高阈值解决了这一问题。
