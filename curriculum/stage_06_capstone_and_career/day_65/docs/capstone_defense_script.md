## 二、10 分钟企业评委高频硬核问答（5 大必考题与满分示范）

### Q1【幻觉治理】（AI 算法与质量评审专家）
- **评委提问**：企业财报与合规场景对准确率要求极高，你们如何治理大模型幻觉？如果 RAG 检索回来的上下文缺失或存在冲突，Agent 怎么避免一本正经地胡说八道？
- **30 秒高分应答模板**：
  1. **检索增强**：采用 `BM25 + 向量` 双路召回与 `RRF` 融合重排，先保证核心证据不漏召；
  2. **强制溯源**：Prompt 约束与解析层强制每条结论绑定文档 ID 与原文 Citation，无证据禁止外推；
  3. **低置信度拒答（Abstention）**：当检索相似度低于阈值或财报口径冲突时，直接触发拒答并提示人工复核；
  4. **评测门禁**：CI/CD 集成 `Faithfulness` 与 `Context Recall` 离线评测，低于 `0.85` 自动阻断发布。

### Q2【高并发成本】（CTO / FinOps 架构负责人）
- **评委提问**：如果在集团内推广，早高峰 500 并发同时调用多 Agent + 长文档 RAG，Token 成本和 P99 延迟怎么控制？会不会把预算打爆？
- **30 秒高分应答模板**：
  1. **语义缓存（Semantic Cache）**：高频重复的制度/财报摘要问答直接命中缓存返回，实测削减 35%-45% LLM 调用；
  2. **大小模型分级路由（Model Router）**：简单意图与格式抽取路由至轻量模型，仅复杂多步推理调用旗舰模型；
  3. **上下文裁剪与压缩**：检索 Chunk 去重 + 动态 Top-K 预算控制，压低无效输入 Token；
  4. **网关限流与熔断**：实施租户级 Token 配额、并发信号量与降级开关，守住成本红线与 P99 延迟。

### Q3【权限隔离】（信息安全与合规总监）
- **评委提问**：不同部门（如财务部、法务部、普通员工）共用一套向量库，如何防止越权检索？如果有人通过 Prompt 注入诱导 Agent 套取高管薪酬或未公开财报怎么办？
- **30 秒高分应答模板**：
  1. **检索前过滤（Pre-filtering）**：文档切片入库时强制绑定 `tenant_id`、`dept_acl` 与密级标签，查询条件由 JWT 鉴权后下推至向量库/BM25 过滤层，绝不在召回后过滤；
  2. **纵深输入防御**：网关层部署 Prompt 注入规则与分类器，识别“忽略前文指令/输出系统提示词”等攻击直接拦截；
  3. **PII 脱敏与审计**：用户输入落库前与输出返回前执行身份证/银行卡/手机号脱敏，全链路写入不可篡改审计日志。

### Q4【HITL 超时与幂等】（业务运维与风控 VP）
- **评委提问**：你们设计了高风险动作的 HITL 人工审批挂起机制，但如果审批人出差一直不点通过怎么办？系统重启后挂起的状态会丢吗？审批人重复点击批准会不会导致资金或公告重复执行？
- **30 秒高分应答模板**：
  1. **状态持久化**：审批单（`approvals`）与会话上下文快照持久化至 SQLite/PostgreSQL，进程重启后可通过 `session_id` 无损恢复；
  2. **TTL 超时与升级（Escalation）**：每张审批单设置 TTL，超时自动流转为 `expired` 并触发企微/邮件转派上级或安全自动拒绝；
  3. **CAS 状态机 + 幂等键**：审批接口严格校验 `status == 'pending'`，重复提交直接返回 `409 Conflict`，下游工具配合 `Idempotency Key` 彻底杜绝重复副作用。

### Q5【微调 vs RAG 选型】（首席 AI 架构师）
- **评委提问**：为什么你们选择用混合 RAG + 工作流编排，而不是直接用企业内部文档微调（SFT/LoRA）一个专属大模型？什么情况下你们才会考虑微调？
- **30 秒高分应答模板**：
  1. **职责分离原则**：**RAG 管动态知识，微调管行为模式**。企业财报与制度高频更新且要求严格的文档级 ACL 权限隔离与原句溯源，微调模型无法实时遗忘或按权限屏蔽特定文档；
  2. **微调适用边界**：只有当我们需要固化复杂 `JSON / Tool-Call` 输出格式、统一特定金融合规话术风格、或压缩超长 System Prompt 推理成本时，才会采用小规模 LoRA 微调辅助 RAG。
