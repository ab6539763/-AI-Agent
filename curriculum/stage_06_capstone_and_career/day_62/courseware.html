一、全栈 SSE 流式交互与 HITL 闭环架构

前端通过 fetch + ReadableStream 消费后端 POST /api/v1/capstone/chat/stream 推送的多事件 SSE 帧（status → citations → token → hitl_required → done），并在高风险挂起时联动 POST /api/v1/capstone/approve 完成状态闭环。

flowchart LR UI["frontend/index.html 分析台"] -->|"POST /api/v1/capstone/chat/stream"| API["FastAPI + CORSMiddleware"] API --> SEC["PII 脱敏 & 注入检测"] SEC -->|"安全通过"| RAG["HybridFinancialRAG (BM25 + 向量 RRF)"] RAG -->|"SSE: citations"| UI RAG --> GEN["流式生成 + HITL 风险识别"] GEN -->|"SSE: token / hitl_required"| UI UI -->|"POST /api/v1/capstone/approve"| HITL["resolve_hitl() 审批闭环"] HITL --> DB[("SQLite: sessions / messages / approvals")] GEN --> DB UI -->|"GET /api/v1/capstone/history/{session_id}"| DB

核心思考：为什么 POST SSE 接口在生产环境必须设置 X-Accel-Buffering: no？

Nginx 等反向代理默认开启响应缓冲，会等待后端输出达到缓冲区阈值后才一次性转发给浏览器，导致 SSE 流式打字机效果退化为长时间卡顿。设置 X-Accel-Buffering: no 可强制代理逐帧透传。
