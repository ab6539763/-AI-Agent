flowchart LR RAW["原始简历草稿 / STARBullet"] --> AUDIT["audit_resume_bullets()"] AUDIT --> CHECK1["量化指标检查 (%, ms, Recall, QPS)"] AUDIT --> CHECK2["AI 技术词检查 (RAG, HITL, MCP, SSE)"] AUDIT --> CHECK3["强动作动词检查 (主导/设计/重构)"] README["GitHub README.md"] --> RAUDIT["audit_github_readme()"] RAUDIT --> SCORE["6大维度加权评分 (0-100 / A-D)"] CHECK1 & CHECK2 & CHECK3 --> GEN["generate_resume_markdown()"] GEN --> ROLES["AI App / Agent / RAG Engineer 定制简历"]

三、Before / After 实战改写对照

❌ 改写前（容易被初筛淘汰）

“参与公司智能体平台开发，使用大模型和向量数据库做了问答和审批功能，运行稳定，效果不错。”

诊断：动词偏弱（参与）、无具体架构词（未提 BM25/RRF/HITL/SSE）、无任何量化结果。

✅ 改写后（STAR 高亮版）

“针对高风险资金划拨存在越权风险，主导构建 HITL 审批闭环；基于 FastAPI SSE 与 SQLite 状态机实现幂等流转与 PII 脱敏，高风险动作 100% 人工复核，重复审批拦截率 100%，通过 25 项 pytest 回归。”

五、课后自测思考题

1. GitHub README 满分 100 分的 6 大检查维度分别是什么？

系统架构图（20分）、Quickstart 可复现命令（20分）、API 接口文档（20分）、量化评测基线（20分）、Demo GIF/截图（10分）、开源协议 License（10分）。

2. 为什么投递 Agent Engineer 与 RAG Engineer 不能共用同一份排序的简历？

面试官前 15 秒只看前两条项目经历。generate_resume_markdown() 会依据岗位画像中的 priority_keywords 与 role_tags 动态把最契合的项目置顶，最大化首屏匹配度。
