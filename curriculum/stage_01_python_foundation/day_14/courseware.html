二、项目一系统架构与交互闭环

为了兼顾线上真实大模型调用与离线 CI 自动化测试，我们在 LLMClient 中设计了双通道切换机制：检测到 OPENAI_API_KEY 时直连在线 API；未配置 Key 时自动回退至 httpx.MockTransport 离线模拟通道。

flowchart LR User["用户输入"] --> Router{"是否以 / 开头?"} Router -- "是: 斜杠指令" --> Cmd["handle_command()
/clear /save /load /stats /exit"] Router -- "否: 对话文本" --> Ask["ask() 追加 user 消息"] Ask --> Client["LLMClient.chat_completion()
@retry_on_error 指数退避"] Client --> Transport{"API Key 是否存在?"} Transport -- "是" --> Live["Live OpenAI API"] Transport -- "否" --> Mock["httpx.MockTransport"] Client -- "失败" --> Rollback["pop() 回滚未提交 user 消息"] Client -- "成功" --> Commit["追加 assistant 消息并累加 Token"]

三、核心斜杠命令与工程亮点

1. 事务性异常回滚（杜绝脏上下文）

在多轮对话中，如果第 N 轮请求因为网络超时或 401 鉴权失败而报错，已经 append 进 messages 的用户提问必须立即 pop() 回滚，否则下一轮发送给大模型时会出现连续两条 user 消息的畸形上下文。

try:
    response = self.client.chat_completion(self.messages, temperature=self.temperature)
except ZhiShuError:
    self.messages.pop()  # 事务回滚：保证上下文始终成对完整
    raise

2. 斜杠命令速查表

指令功能说明工程细节
/clear清空对话历史保留初始 System Prompt，并重置轮数与 Token 计数
/save <path>导出会话 JSON自动创建父目录，写入版本、时间戳、统计与完整消息列表
/load <path>恢复历史会话校验文件存在性与 JSON 合法性，失败抛出 CommandError
/stats查看运行统计展示模型名、Mock/Live 模式、轮数与三项 Token 消耗
/exit退出 CLI 循环返回终止信号 (False, ...)，优雅结束会话
