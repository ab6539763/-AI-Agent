二、下午实战：Contacts CRUD + JSON 持久化核心代码

2.1 核心模块设计（zhishu_agent/contacts.py）

在实际企业项目中，CRUD 接口必须遵循“先校验、再操作、显式抛异常”原则。以下核心代码可直接运行验证：

import json
from pathlib import Path
from typing import Any

VALID_AGENT_TYPES = {"human", "agent"}

def add_contact(
    contacts: list[dict[str, Any]],
    name: str,
    role: str,
    department: str = "AI 研发部",
    agent_type: str = "human",
    skills: list[str] | None = None,
) -> dict[str, Any]:
    clean_name = name.strip()
    clean_role = role.strip()
    if not clean_name or not clean_role:
        raise ValueError("姓名与岗位均不能为空")
    if agent_type.lower() not in VALID_AGENT_TYPES:
        raise ValueError(f"非法类型: {agent_type}")
    if any(c["name"].lower() == clean_name.lower() for c in contacts):
        raise ValueError(f"联系人已存在: {clean_name}")

    contact = {
        "name": clean_name,
        "role": clean_role,
        "department": department.strip() or "AI 研发部",
        "agent_type": agent_type.lower(),
        "skills": [s.strip() for s in (skills or []) if s.strip()],
    }
    contacts.append(contact)
    return contact

def save_contacts(filepath: Path | str, contacts: list[dict[str, Any]]) -> None:
    target = Path(filepath)
    target.parent.mkdir(parents=True, exist_ok=True)
    with target.open("w", encoding="utf-8") as f:
        json.dump(contacts, f, ensure_ascii=False, indent=2)

2.2 课堂要点笔记（Tech Lead 张工划重点）

  • 防坑 1（仅限位置参数 /）：update_contact(contacts, target_name, /, **updates) 允许调用方传入 name="新名字" 而不会触发 Python 参数重名报错。
  • 防坑 2（中文不乱码）：持久化 JSON 必须同时指定 encoding="utf-8" 与 ensure_ascii=False。
  • 防坑 3（返回副本）：list_contacts 返回新列表副本，防止外部直接 .clear() 破坏内部数据。

三、晚上验收：第 1 周随堂自测（可折叠查看答案）

自测题 1：为什么 save_contacts 要先调用 target.parent.mkdir(parents=True, exist_ok=True)？

点击展开答案与解析

答案：Python 的 open(filepath, "w") 不会自动创建不存在的父目录，否则会直接抛出 FileNotFoundError。使用 mkdir(parents=True, exist_ok=True) 可以递归建好缺失目录并在目录已存在时安全跳过。

自测题 2：在 pytest 中测试 save_contacts 和 load_contacts 时，应该把测试文件写在哪里？

点击展开答案与解析

答案：使用 pytest 内置的 tmp_path 夹具（例如 tmp_path / "contacts.json"）。它会自动为每个测试函数创建独立的临时目录，测试完成后自动清理，绝不污染项目源码仓库。
