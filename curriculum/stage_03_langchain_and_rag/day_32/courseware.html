一、Advanced RAG Part 1 架构流水线

从用户原始提问到高信噪比压缩上下文，完整数据流转如下：

flowchart TD U["用户提问 + 对话历史"] --> QR["QueryRewriter (指代消解 + 口语清洗)"] QR --> MQ["MultiQueryRetriever (多视角变体 + RRF 去重)"] QR --> HYDE["HyDERetriever (假设文档生成 + 向量检索)"] MQ --> RAW["召回原始切片集合"] HYDE --> RAW RAW --> CC["ContextCompressor (句级打分过滤 + 保序拼接)"] CC --> LLM["高信噪比上下文 -> 注入 LLM 生成答案"]

二、四大核心组件拆解

组件名称解决痛点核心机制
QueryRewriter 多轮指代模糊、口语冗余词干扰 结合 chat_history 替换代词，清洗前后缀并扩展同义词
MultiQueryRetriever 单一问法表达偏差导致漏召回 生成 num_queries 个视角变体并行检索，RRF 融合去重
HyDERetriever 短问句与长文档语义分布不对齐 先生成假设答案文档，再用假设文档向量检索真实知识库
ContextCompressor 切片噪音多、Token 浪费、Lost in the Middle 句级相关性打分过滤，仅保留高相关句子并保持原文语序

核心调用示例

from zhishu_agent import (
    ContextCompressor, HyDERetriever, LocalVectorStore, MultiQueryRetriever, QueryRewriter
)

# 1. 查询改写
rewriter = QueryRewriter()
clean_q = rewriter.rewrite("请问一下它一般有几天呀？", chat_history=[{"role": "user", "content": "年假制度"}])

# 2. Multi-Query 多路召回 + RRF 去重
mq = MultiQueryRetriever(retriever=store.as_retriever(search_kwargs={"k": 2}), num_queries=3)
docs, variants = mq.retrieve_with_details("年假几天", k=2)

# 3. HyDE 假设文档检索
hyde = HyDERetriever(vector_store=store, k=2)
hypo_doc, hyde_docs = hyde.retrieve_with_hypothesis("Pod 老是 OOM 怎么办")

# 4. 上下文压缩
compressor = ContextCompressor(min_score=0.18, max_sentences_per_doc=2)
compressed = compressor.compress_documents("年假有几天", docs)

点击查看：为什么 ContextCompressor 筛选后要恢复原文句子顺序？

如果只按相关性分数从高到低拼接句子，可能会把“结论句”排在“前提条件句”前面，破坏逻辑连贯性。按分数挑选 Top-N 句子后，再按原文索引 idx 升序排列，既能剔除噪音，又能保证大模型读到通顺的上下文。
