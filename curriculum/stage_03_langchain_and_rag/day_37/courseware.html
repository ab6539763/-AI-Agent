三、SSE 前端消费与引用卡片实战

1. 为什么用 fetch() + ReadableStream 消费 SSE？

浏览器原生 EventSource 仅支持 GET 请求，无法携带 JSON 请求体。通过 fetch() 发起 POST 请求并读取 response.body.getReader()，即可按 \n\n 分帧解析 token 与 citations：

const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
let buffer = "";

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() || "";
  for (const block of blocks) {
    if (!block.trim().startsWith("data: ")) continue;
    const evt = JSON.parse(block.trim().slice(6));
    if (evt.type === "token") textSpan.textContent += evt.content;
    if (evt.type === "citations") renderCitationCards(div, evt.citations);
  }
}

四、随堂思考与课后自测

思考题 1： 如果用户上传文档后重启了 FastAPI 服务，之前上传的文档和历史对话里的引用卡片会丢失吗？

点击查看参考答案

不会丢失。KBDatabase 将文档原文持久化在 kb_documents 表，将引用列表以 JSON 格式持久化在 messages.citations_json 字段。create_app() 启动时会自动调用 db.load_documents() 重建知识库索引。

思考题 2： 如何验证 TestClient 收到的 SSE 流既包含逐字 token，又包含可溯源的 citations？

点击查看参考答案

使用 with client.stream("POST", "/api/v1/kb/chat/stream", json=...) as resp: 读取 resp.iter_text()，按 \n\n 切分后解析 data: 前缀的 JSON，分别过滤 type == "token" 与 type == "citations" 即可完成端到端断言。
