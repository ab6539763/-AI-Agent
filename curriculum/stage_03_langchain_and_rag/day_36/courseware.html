一、系统端到端架构总览

EnterpriseKBService 将离线入库链路与在线问答链路解耦为四大核心层级：

flowchart LR A["多格式上传 (.txt / .md / .csv)"] --> B["解析与智能切分"] B --> C["BM25 + 向量双路索引"] Q["用户提问"] --> D["混合检索 + RRF 融合"] C --> D D --> E["Rerank 精排"] E -->|"高于阈值"| F["带 [1][2] 引用回答"] E -->|"低于阈值"| G["安全拒答"] F --> H[("SQLite 会话历史")] G --> H

二、四大核心模块设计拆解

模块 核心类 / 方法 关键工程设计
多格式解析入库 ingest_file() / _parse_and_chunk() .txt 滑动窗口切分；.md 保留章节标题上下文；.csv 逐行转键值对文本
混合检索与精排 retrieve() / _compute_rerank_score() BM25 稀疏检索 + LocalEmbedding 余弦检索 + RRF(k=60) + 精排重排序
引用溯源与拒答 ask() / Citation 生成内联编号 [1][2] 与来源片段；低于 min_relevance_score 时触发安全拒答
SQLite 会话存储 SQLiteSessionStore 持久化 sessions 与 messages 表（含 citations_json），支持重启恢复

三、核心代码实战：EnterpriseKBService 全链路运行

from pathlib import Path
from zhishu_agent import EnterpriseKBService

kb = EnterpriseKBService(db_path="kb_sessions.db", chunk_size=200, chunk_overlap=30)
kb.ingest_text(
    "# Redis 规范\n生产环境 Redis 集群严禁执行 KEYS * 命令，应使用 SCAN 分批遍历。",
    source="sre_runbook.md",
    file_type=".md",
)

resp = kb.ask("生产环境 Redis 禁止执行什么命令？", session_id="ops-001")
print(resp.format_with_sources())
print("历史消息数:", len(kb.get_session_history("ops-001")))
kb.close()

四、课后思考与练习

思考 1：为什么解析 Markdown（.md）时要把上级标题（如 ## 熔断策略）保留在每个子切片的开头？

点击查看解析

当一篇长文档按长度切分成多个 Chunk 后，靠后的切片往往只包含正文细节而缺少主语（例如只写了“超过 5% 触发自动操作”）。保留章节标题前缀相当于为切片注入了结构化上下文，能大幅提升 BM25 和向量检索的召回准确率。

思考 2：为什么把 citations_json 一并存入 SQLite 的 messages 表，而不是只存纯文本回答？

点击查看解析

企业级知识库前端在用户刷新页面或切换历史会话时，需要重新渲染回答下方的“可点击来源卡片（文件名、切片编号、原文片段）”，同时也便于合规审计人员追溯每一次 AI 回答的历史依据。
