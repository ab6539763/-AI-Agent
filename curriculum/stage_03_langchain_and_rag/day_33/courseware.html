一、四段式高级 RAG 检索流水线

从用户提问到最终输出高信噪比父文档上下文，完整数据流如下：

flowchart LR Q["用户提问 Query"] --> BM25["BM25Retriever 稀疏检索"] Q --> VEC["VectorRetriever 向量检索"] BM25 --> RRF["reciprocal_rank_fusion (k=60)"] VEC --> RRF RRF --> RERANK["CrossEncoderReranker 精排"] RERANK --> PARENT["ParentDocumentRetriever 子切片映射父文档"] PARENT --> CTX["高信噪比完整上下文"]

二、四大核心组件拆解

1. BM25 vs 向量检索（双路互补）

检索方式擅长场景典型短板
BM25Retriever（稀疏词法）精确错误码、工单号、专有名词、稀有词同义词/语义改写（如“年假” vs “带薪休假”）召回弱
VectorRetriever（稠密语义）语义相似、口语化提问、跨表达匹配精确编号、超短关键词容易被语义稀释

2. RRF 倒数排名融合（reciprocal_rank_fusion）

公式：RRF(d) = sum(1 / (k + rank(d)))（默认平滑常数 k = 60）。无需对 BM25 与余弦相似度做分数归一化，即可稳健合并多路排名并放大“共识文档”权重。

3. Cross-Encoder 精排（CrossEncoderReranker）

bm25_hits = bm25.retrieve(query, top_k=5)
vec_hits = vector.retrieve(query, top_k=5)
fused_docs = [doc for doc, _ in reciprocal_rank_fusion([bm25_hits, vec_hits], k=60)]
top_docs = CrossEncoderReranker().rerank(query, fused_docs, top_k=3)

4. 父文档检索（ParentDocumentRetriever）

采用 Small-to-Big 策略：入库时将长文档切分为细粒度子切片建立混合索引；检索时先定位最精确的子切片，再按 parent_id 去重映射回完整父文档，兼顾“检索精度”与“LLM 上下文完整度”。

点击查看：为什么 RRF 比直接把 BM25 分数和 Cosine 分数相加更好？

BM25 分数无上界（可能为 0~25+），而余弦相似度固定在 [-1, 1]。直接相加会导致大数吃小数。RRF 只看排名位置 1 / (k + rank)，天然量纲无关且对异常值鲁棒。
