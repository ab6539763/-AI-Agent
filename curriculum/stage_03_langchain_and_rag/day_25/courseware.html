二、三大核心工程组件拆解

1. 标准化消息对象（BaseMessage 家族）

消息类内部 role / type典型业务职责
SystemMessagesystem设定智能体人设、业务边界与输出格式要求
HumanMessageuser封装终端用户的当前提问或指令
AIMessageassistant承载大模型回复正文及 response_metadata（token 用量等）

2. 声明式模板：ChatPromptTemplate.from_messages(...)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是星辰数科的 {role}，擅长 {domain}。"),
    ("human", "请分析：{question}"),
])

# 自动识别占位符: ['role', 'domain', 'question']
prompt_value = prompt.invoke({
    "role": "AI 架构师",
    "domain": "多模型网关",
    "question": "如何零成本切换 DeepSeek 与 Qwen？",
})

3. 无缝切换模型：BaseChatModel 与 get_chat_model

for provider in ("deepseek", "qwen"):
    model = get_chat_model(provider)
    reply = model.invoke(prompt_value)
    print(reply.content)
    print(reply.response_metadata)

思考题：为什么 BaseChatModel 把输入归一化放在 invoke()，而让子类只实现 _generate()？

这是典型的模板方法模式（Template Method）。无论是传字符串、消息列表还是 ChatPromptValue，都在基类 invoke() 中统一转换成 list[BaseMessage]，各厂商子类只需专注处理标准消息列表即可，大幅减少重复代码。
