一、Ragas 四维评估与诊断闭环流水线

Ragas 通过 EvalSample(question, answer, contexts, ground_truth) 将问题精准定位到生成侧或检索侧：

flowchart TD DS["EvalSample (Q, A, Contexts, GT)"] --> EVAL["RAGEvaluator.evaluate_dataset()"] EVAL --> GEN["生成侧 Generation"] EVAL --> RET["检索侧 Retrieval"] GEN --> F["Faithfulness 忠实度 (防幻觉)"] GEN --> AR["Answer Relevancy 相关性 (防跑题)"] RET --> CP["Context Precision 精确率 (Precision@K 排序)"] RET --> CR["Context Recall 召回率 (GT 事实覆盖)"] F --> RPT["EvalReport 聚合报告 & 逐样本诊断"] AR --> RPT CP --> RPT CR --> RPT

二、Ragas 四大核心指标拆解

指标名称 所属阶段 输入依赖 核心计算公式 / 物理意义 低分诊断与优化动作
Faithfulness 生成侧 answer, contexts 被上下文支撑的陈述数 / 回答总陈述数 hallucination_risk：收紧 Prompt 约束、降低 Temperature
Answer Relevancy 生成侧 question, answer 提问与回答的语义相似度 + 核心词覆盖率 low_relevancy：优化意图识别、禁止答非所问
Context Precision 检索侧 question, contexts, ground_truth 基于 Precision@K 衡量相关文档是否排在前列 retrieval_noise：引入 Rerank 重排序、减小 K 值
Context Recall 检索侧 ground_truth, contexts 被上下文覆盖的标准答案事实数 / 标准答案总事实数 missing_context：增大 Top-K、优化 Chunk 或启用混合检索

三、核心代码实战：RAGEvaluator 批量评测与幻觉拦截

from zhishu_agent import EvalSample, RAGEvaluator

samples = [
    EvalSample(
        sample_id="qa-001",
        question="星辰数科入职满1年员工每年有多少天带薪年假？",
        answer="星辰数科入职满1年员工每年享有5天带薪年假，满10年享有10天。",
        contexts=["星辰数科年假制度：入职满1年员工每年享有5天带薪年假，满10年享有10天。"],
        ground_truth="入职满1年员工每年享有5天带薪年假，满10年享有10天。",
    ),
    EvalSample(
        sample_id="qa-002",
        question="生产环境 Redis 集群禁止执行什么命令？",
        answer="生产环境 Redis 集群禁止执行 KEYS * 命令。此外每天凌晨会自动重启集群。",
        contexts=["生产环境 Redis 集群禁止执行 KEYS * 命令，请使用 SCAN 分批遍历。"],
        ground_truth="生产环境 Redis 集群禁止执行 KEYS * 命令，应使用 SCAN 分批遍历。",
    ),
]

report = RAGEvaluator().evaluate_dataset(samples)
print(report.format_summary())
for r in report.sample_results:
    print(r.sample_id, r.diagnostics, r.unsupported_claims)

四、课后思考与练习

思考 1：如果某次 RAG 评测中 Context Recall = 1.0、Context Precision = 1.0，但 Faithfulness = 0.33，问题出在检索器还是大模型？

点击查看解析

问题出在生成侧（大模型）！检索器已经把正确上下文完整且精准地排在最前面送入 Prompt，但大模型没有严格遵循上下文作答，擅自脑补了未经证实的陈述（幻觉）。

思考 2：为什么 Context Precision 不仅看“有没有召回”，还要看“排在第几位”？

点击查看解析

因为大模型存在 Lost in the Middle（中间迷失） 效应，且生产环境会限制上下文窗口或截断 Top-K。如果真正有用的文档排在第 3 位而前 2 位全是噪音，不仅浪费 Token，还会干扰大模型生成质量，因此 Precision@K 会对靠后排名的相关文档进行折损惩罚。
