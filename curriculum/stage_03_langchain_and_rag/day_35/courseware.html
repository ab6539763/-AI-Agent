三、核心代码实战：从目录加载到多轮对话

from zhishu_agent import SimpleDirectoryReader, VectorStoreIndex, compare_frameworks

# 1. 一键加载目录并构建索引
docs = SimpleDirectoryReader("./enterprise_kb").load_data()
index = VectorStoreIndex.from_documents(docs, chunk_size=200, chunk_overlap=40)

# 2. QueryEngine：无状态单轮精准问答
query_engine = index.as_query_engine(similarity_top_k=3, response_mode="compact")
print(query_engine.query("生产环境 Redis 集群禁止执行什么命令？").response)

# 3. ChatEngine：有状态多轮对话（自动改写指代词）
chat_engine = index.as_chat_engine(similarity_top_k=3)
print(chat_engine.chat("入职满1年员工有多少天年假？").response)
print(chat_engine.chat("申请它需要提前几天？").response)

# 4. 架构选型建议
print(compare_frameworks(use_case="hybrid")["recommendation"])

四、课后思考与练习

思考 1：LlamaIndex 为什么要把 Document 进一步切分为带 SOURCE / PREVIOUS / NEXT 关系的 Node，而不是直接存纯文本列表？

点击查看解析

当检索器命中某一个细粒度切片（Node）时，往往存在“上下文被截断”的问题。通过维护 PREVIOUS 和 NEXT 节点指针，系统可以在检索后自动扩展相邻上下文（Sentence Window / Small-to-Big Retrieval），既保证了向量匹配的精准度，又保证了送入大模型上下文的完整性。

思考 2：在企业级智能体项目中，什么时候应该选择“LlamaIndex + LangGraph 混合架构”？

点击查看解析

当业务既要求高精度私有知识库检索（多文档、多格式、复杂溯源），又要求复杂决策流与外部动作执行（如查完制度后自动调用 OA/Jira API 提交审批、支持人工中断确认）时，混合架构是最优解：LlamaIndex 负责做“最强的知识大脑”，LangGraph 负责做“最稳的行动中枢”。
