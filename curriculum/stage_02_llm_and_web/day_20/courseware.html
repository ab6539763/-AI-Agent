🎙️ 讲师旁白（从“关键词匹配”到“语义向量”）：
在企业知识库问答中，用户问“出差票据怎么报”，而文档写的是“差旅费用和发票怎么提交报销？”——两者字面并不完全重合，传统的 in 或 SQL LIKE 检索会直接失效。通过 Embedding 把文本映射到高维向量空间，再用余弦相似度衡量语义方向夹角，智能体就能真正“听懂”用户的意图。今天我们还将同时打通 Vision 多模态消息封装，让智枢平台既能“看图”也能“搜义”！

一、语义 FAQ 检索核心架构图

一次完整的语义检索包含离线建库向量化与在线余弦相似度 Top-K 召回两个环节：

flowchart LR A["用户提问 Query"] --> B["LocalEmbeddingModel (Unigram + Bigram + L2 归一化)"] B --> C["Query 单位向量"] D["企业知识库 FAQ"] --> E["预计算 FAQ 向量索引"] C --> F["cosine_similarity 计算夹角余弦"] E --> F F --> G["降序排序 & min_score 过滤"] G --> H["Top-K 语义匹配结果 (FAQMatch)"]

二、核心组件与协议规范

1. OpenAI Vision 多模态消息格式

build_multimodal_message(text, image_url, detail="auto") 将 content 封装为结构化列表：

{
  "role": "user",
  "content": [
    {"type": "text", "text": "请识别这张报销发票上的金额与开票日期。"},
    {"type": "image_url", "image_url": {"url": "https://example.xingchen.local/invoice.png", "detail": "high"}}
  ]
}

2. 核心模块能力对照表

符号名称核心职责工程亮点
build_multimodal_message构造 Vision 多模态消息载荷校验空文本/空 URL 与 detail 枚举
LocalEmbeddingModel纯 Python 确定性向量编码器基于 hashlib.md5 特征哈希 + L2 归一化，无 numpy 依赖
cosine_similarity计算两向量余弦相似度支持零向量兜底、维度校验与 [-1, 1] 钳位
SemanticFAQMatcher语义 FAQ 索引与 Top-K 检索预计算问题向量，支持 top_k 与 min_score 过滤

点击查看：为什么 LocalEmbeddingModel 不能用 Python 内置的 hash()？

Python 3 默认启用了 PYTHONHASHSEED 随机化，内置 hash("报销") 在不同进程中会返回完全不同的整数。使用 hashlib.md5 做特征哈希可以保证任何机器、任何进程生成的向量 100% 一致。
