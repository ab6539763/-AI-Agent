为了兼顾工具参数解析的可靠性与用户交互的实时性，IntegratedAgent.stream_reply() 采用两阶段协同架构：

flowchart TD U["用户输入"] --> CP["记录事务 checkpoint 并追加 role=user"] CP --> R1["阶段一：工具决策循环 (stream=False, tools=...)"] R1 -->|"返回 tool_calls"| EX["ToolRegistry.dispatch() 执行本地工具"] EX --> R1 R1 -->|"无 tool_calls"| ST["阶段二：SSE 流式输出 (stream=True)"] ST --> Y["iter_lines() + parse_sse_line() 逐块 yield"] Y --> SV["追加完整 assistant 消息并更新统计"] R1 -.->|"异常 / 超限"| RB["del messages[checkpoint:] 事务回滚"] ST -.->|"HTTP 异常"| RB

点击查看：为什么工具决策阶段用非流式，最终回复阶段才用 SSE 流式？

在工具决策阶段，模型输出的是结构化 JSON 参数（tool_calls），必须等 JSON 完整接收后才能反序列化并执行本地函数，流式分片无法提前触发执行；而在工具结果已收集完毕、进入最终自然语言总结阶段时开启 stream=True，既保证了工具调用零解析错误，又能让用户第一时间看到逐字吐出的回复。
