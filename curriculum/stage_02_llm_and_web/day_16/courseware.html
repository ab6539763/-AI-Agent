一、LLM API 核心生成参数全景

参数名 合法范围 核心作用与工程选型建议
temperature [0.0, 2.0] 控制采样随机性。财务/代码/SQL 提取建议 0.0 ~ 0.2；创意文案建议 0.9 ~ 1.3。
top_p (0.0, 1.0] 核采样（Nucleus Sampling），只从累积概率达 top_p 的候选词中采样；通常与 temperature 二选一主调。
max_tokens [1, 128000] 限制单次最大输出长度，防止死循环生成导致高额 Token 费用。
frequency_penalty [-2.0, 2.0] 频率惩罚，正值按词频惩罚已出现词汇，有效抑制“车轱辘话”。
stream bool 设为 True 时服务端返回 text/event-stream 分片流，显著降低首字延迟（TTFT）。

二、SSE 流式传输时序与 [DONE] 终止机制

三、核心模块代码速览

1. 强校验参数模型与 SSE 解析（zhishu_agent/stream_client.py）

class GenerationConfig(BaseModel):
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)
    top_p: float = Field(default=1.0, gt=0.0, le=1.0)
    max_tokens: int = Field(default=1024, ge=1, le=128000)
    frequency_penalty: float = Field(default=0.0, ge=-2.0, le=2.0)
    stream: bool = Field(default=True)

def parse_sse_line(line: str) -> str | None:
    stripped = line.strip()
    if not stripped or stripped.startswith(":") or not stripped.startswith("data:"):
        return None
    payload = stripped[len("data:"):].strip()
    if not payload or payload == "[DONE]":
        return None
    data = json.loads(payload)
    return data["choices"][0]["delta"].get("content")

四、随堂互动自测

问题 1： 为什么在 stream_chat() 中遇到 data: [DONE] 后必须显式 break，而不是仅仅依赖 parse_sse_line() 返回 None？

点击查看参考解析

显式 break 可以立即终止流式迭代并释放底层 HTTP 连接；如果仅返回 None 而继续循环，一旦上游网关或代理在 [DONE] 之后附带异常心跳或脏数据帧，客户端就会误解析并污染最终输出。

问题 2： 如果同时将 temperature 设为 0.0 且把 top_p 设为 1.0，模型的输出会偏随机还是偏确定？

点击查看参考解析

偏确定（接近贪心解码）。当 temperature=0.0 时，最高概率 Token 的权重被极致放大，即使 top_p=1.0 保留了全词表，模型几乎每次都会稳定选择概率最大的那个词。
