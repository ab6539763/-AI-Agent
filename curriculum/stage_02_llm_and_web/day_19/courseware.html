🎙️ 讲师旁白（破除黑盒）：
很多同学以为 Function Calling 是“大模型在云端替我们执行了 Python 函数”——这是一个常见的误解！事实上，大模型永远不会直接执行你的本地代码。它只负责根据你提供的 JSON Schema，在 Round 1 返回一段结构化的意图声明（tool_calls）；真正执行函数、查询数据库、再把结果通过 role="tool" 回传给模型的，是我们自己的 ToolCallingAgentLoop 引擎。今天，我们就用纯 API 把这套协议彻底打通！

一、Pure-API Function Calling 两轮交互协议

在标准 OpenAI /v1/chat/completions 协议中，一次完整的工具调用通常包含 2 轮 HTTP 请求：

sequenceDiagram actor User as 用户 participant Loop as ToolCallingAgentLoop participant LLM as OpenAI API / MockTransport participant Reg as ToolRegistry (本地执行) User->>Loop: run("查北京天气并计算 (120+80)*3/4") Loop->>LLM: Round 1 POST /chat/completions (含 tools Schema) LLM-->>Loop: assistant message (finish_reason="tool_calls") Loop->>Reg: dispatch("get_weather", ...) & dispatch("calculate_math", ...) Reg-->>Loop: 返回 JSON 字符串结果 Loop->>LLM: Round 2 POST /chat/completions (追加 assistant + role="tool") LLM-->>Loop: assistant message (finish_reason="stop", 最终自然语言回复) Loop-->>User: 返回 AgentRunResult

2. 安全红线：为什么严禁 eval()？

如果直接把大模型生成的字符串传给 Python 的 eval(expression)，一旦遭遇 Prompt 注入（如 __import__('os').system('rm -rf /')），服务器将直接沦陷。因此我们必须使用 ast.parse(..., mode="eval") 白名单求值器：

def _eval_ast_node(node: ast.AST) -> int | float:
    if isinstance(node, ast.Constant):
        if isinstance(node.value, bool) or not isinstance(node.value, (int, float)):
            raise ValueError("不允许的常量类型")
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _BINARY_OPS:
        return _BINARY_OPS[type(node.op)](_eval_ast_node(node.left), _eval_ast_node(node.right))
    raise ValueError(f"检测到不安全的表达式语法节点: {type(node).__name__}")

点击查看：遇到模型幻觉出未知工具名怎么办？

ToolRegistry.dispatch() 不会直接抛出 KeyError 崩溃，而是返回 {"error": "未知工具: ...", "available_tools": [...]} 作为 role="tool" 的内容回传给模型，既保持了 tool_call_id 配对完整性，又让模型有机会在 Round 2 自我纠错。
