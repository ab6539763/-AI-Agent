一、FastAPI 请求处理生命周期与架构流转

当客户端向 FastAPI 发送 HTTP 请求时，请求会先经过 Starlette 路由分发，再由 Pydantic v2 对路径参数、查询参数和 JSON 请求体进行强类型解析与业务校验，全部通过后才进入业务逻辑函数。

sequenceDiagram autonumber actor Client as 调用方 (前端 / TestClient) participant Router as FastAPI 路由分发 participant Pydantic as Pydantic v2 校验层 participant Handler as 业务处理器 Client->>Router: POST /api/v1/chat (JSON) Router->>Pydantic: 校验 ChatRequest alt 校验失败 (空白消息 / 温度越界 / 未知模型) Pydantic-->>Client: 422 Unprocessable Entity else 校验通过 Pydantic->>Handler: 注入强类型 payload Handler-->>Client: 200 OK (ChatResponse JSON) end

二、核心知识点：路由、Path/Query 参数与 Pydantic 模型

1. 三大核心端点设计（zhishu_agent/api_server.py）

HTTP 方法与路径参数类型核心职责与状态码
GET /api/v1/health 无参数 健康检查探针，返回 200 OK 与版本号 0.2.0-day23
GET /api/v1/models/{model_id} Path (model_id) + Query (include_pricing, detail_level) 查询模型元信息；存在返回 200 OK，不存在返回 404，参数非法返回 422
POST /api/v1/chat JSON Body (ChatRequest) 执行智能体对话并返回 ChatResponse（含 Token 统计与延迟）

2. Pydantic v2 请求体与自定义校验器

class ChatRequest(BaseModel):
    message: str = Field(..., min_length=1, max_length=4000)
    model: str = Field(default="deepseek-chat")
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)
    max_tokens: int = Field(default=512, ge=1, le=8192)
    session_id: str | None = Field(default=None, max_length=64)

    @field_validator("message")
    @classmethod
    def validate_message_not_blank(cls, value: str) -> str:
        stripped = value.strip()
        if not stripped:
            raise ValueError("message 不能为空或仅包含空白字符")
        return stripped

三、进程内零端口测试：fastapi.testclient.TestClient

在开发与 CI 阶段，我们无需每次都手动启动 uvicorn 进程。借助基于 httpx 的 TestClient(app)，可以直接在内存中模拟完整 HTTP 请求与状态码断言：

from fastapi.testclient import TestClient
from zhishu_agent.api_server import app

client = TestClient(app)
assert client.get("/api/v1/health").status_code == 200
assert client.post("/api/v1/chat", json={"message": "   "}).status_code == 422
💡 思考题：为什么 GET /api/v1/models/unknown-model 返回 404，而 POST /api/v1/chat 传入未知模型返回 422？

在 REST 语义中，URL 路径里的 {model_id} 代表“资源定位”，资源不存在应返回 404 Not Found；而 POST /api/v1/chat 请求体中的 model 字段属于“表单/载荷参数校验”，不满足 ChatRequest 的 @field_validator 约束时由 Pydantic 拦截并返回 422 Unprocessable Entity。
