# 01. 立项章程 (Project Charter) — Project P06 政务服务与企业政策通智能体

## 1. 项目背景与目标
市民与企业在办理政务审批、申领研发补贴或人才安居补助时，常面临政策文件分散、条款理解门槛高、多部门权责交叉以及个人/企业敏感信息（PII）泄露风险。本项目（P06）旨在构建一套 **100% 离线确定性、可审计、带人工复核（HITL）** 的政务服务与企业政策通智能体。

### 核心业务目标
- **精准政策匹配与条款级引用**：基于政务本体（GovTech Ontology）与政策 Markdown 知识库（LLM Wiki），实现多规则资格核验与精确到条文的引用（如 `POL-2026-TECH-01 §第4条`）。
- **零幻觉拒答机制**：当知识库与本体均无现行有效政策支持时，系统必须确定性拒答（Refusal），严禁编造补贴承诺。
- **PII 隐私脱敏与全链路审计**：在检索与推理前自动脱敏身份证号、统一社会信用代码（USCC）、手机号、银行卡号及邮箱，并写入不可变审计日志。
- **人机协同（HITL）审批闭环**：高额补贴或正式行政给付自动生成 `pending_approval` 工单，必须由业务经办人（Case Officer）签批后方可生效。

## 2. 干系人 (Stakeholders)
| 角色 | 职责 | 关注点 |
|---|---|---|
| 政务服务中心 / 数据局 | 业务发起方与平台监管 | 合规性、跨部门路由准确性、零幻觉 |
| 科技局 / 人社局 / 工信局 | 业务主管部门与审批人 | 资格规则准确性、HITL 签批留痕 |
| 企业与市民申请人 | 终端服务对象 | 响应速度、隐私保护、明确办理指引 |
| FDE 交付团队 | 本体建模、知识库与 API 交付 | 测试覆盖率、可观测性、容器化交付 |

## 3. 范围边界 (Scope)
- **In Scope**: `GovOntologyRegistry` 多规则评估与部门路由、`GovTechLLMWiki`（`index.md` / `log.md` / `entities/<id>.md` + `lint()`）、`GovTechFDEPipeline`（PII 脱敏、条款引用、拒答、HITL 签批、审计日志）、FastAPI 服务与容器化部署、自动化 Pytest 验证。
- **Out of Scope**: 外部公网大模型 API 调用、政务内网核心数据库直连（本版本通过标准 REST API 与离线本体解耦）。
